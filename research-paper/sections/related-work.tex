\section{Background and Related Work}
\label{sec:related}

\subsection{Static Analysis for Security}
Static analysis reasons about a program without running it. Security-oriented
analysers range from lightweight syntactic linters to whole-program
data-flow and taint engines~\cite{chess2004}. Industrial deployments such
as Coverity~\cite{bessey2010} and Infer~\cite{distefano2019} demonstrated
that inter-procedural analysis scales to very large codebases, while
\mbox{FindBugs}/SpotBugs showed that even simple bug patterns catch real
defects at low cost~\cite{ayewah2008}. The code-property-graph
formulation of Yamaguchi \textit{et~al.}~\cite{yamaguchi2014} and the
declarative query model of CodeQL~\cite{avgustinov2016} made it practical
to express security queries as reusable, shareable rules; open tools such
as Semgrep~\cite{semgrep} and Bandit~\cite{bandit} brought the same idea
to a broad developer audience. A persistent finding across this
literature, however, is that adoption is limited less by analysis power
than by developer experience: false positives, missing context, and poor
result presentation drive users away~\cite{johnson2013,nachtigall2022}.
\cs\ uses a curated set of pattern detectors for the high-precision,
high-severity classes---hard-coded secrets, injection sinks, unsafe
deserialisation, request-forgery patterns---and delegates the
context-dependent judgement to its LLM stage rather than expanding the
rule set indefinitely.

\subsection{Software Metrics and Structural Health}
Cyclomatic complexity~\cite{mccabe1976} remains the most widely used
measure of control-flow intricacy and correlates with defect density and
test effort; the Maintainability Index~\cite{coleman1994} combines it
with size and Halstead volume into a single maintainability figure.
\cs\ computes per-function cyclomatic complexity, surfaces the highest-risk
functions, and feeds the mean value into its composite score, treating
structural debt as a first-class signal alongside security findings.

\subsection{Dynamic Analysis and Sandboxing}
Dynamic techniques observe a program as it executes. Fuzzing has become
the dominant automated bug-finding method for native
code~\cite{manes2021}, and container isolation is now the standard way to
run untrusted or unknown software with bounded
privileges~\cite{merkel2014docker}. \cs\ does not fuzz; instead it builds
the project into a Docker image (generating a Dockerfile when none is
present), runs it under CPU and memory limits, and records build time,
start-up latency, and a stream of resource and behavioural events. The
goal is a fast, low-configuration ``does it run, and how does it
behave'' check that complements the static passes.

\subsection{Language Models for Code and Security}
LLMs trained on source code~\cite{chen2021codex} can summarise, review,
and transform programs, and a growing body of work evaluates them
specifically for security. Pearce \textit{et~al.}\ studied the security
of code \emph{generated} by Copilot~\cite{pearce2022} and later the use
of LLMs for \emph{zero-shot vulnerability repair}~\cite{pearce2023};
Khoury \textit{et~al.}~\cite{khoury2023} assessed the security of
ChatGPT-generated code. Learning-based detectors such as
Devign~\cite{zhou2019devign} and LineVul~\cite{fu2022linevul} predict
vulnerable functions or lines directly, though subsequent studies caution
that reported accuracy is sensitive to dataset
quality~\cite{steenhoek2023,croft2023}. \cs\ takes a pragmatic position:
it uses a small, locally hosted instruction-tuned model
(\mbox{Llama~3.2}~\cite{touvron2023llama2}) to produce structured,
schema-constrained findings for each file, and it always presents the
model's output next to the pattern-based result and the offending source,
so a human makes the final call.

\subsection{Security of LLM-Integrated Applications}
As applications embed LLMs, a new weakness class has emerged. Prompt
injection---direct~\cite{perez2022ignore} or indirect through retrieved
content~\cite{greshake2023}---lets an attacker override a system prompt,
and the OWASP Top~10 for LLM Applications~\cite{owaspllm2025} additionally
enumerates insecure output handling, training-data and model poisoning,
sensitive-information disclosure, and excessive agency. Retrieval-augmented
generation~\cite{lewis2020rag} widens the surface further by introducing a
document loader, an embedding store, and a reranker, each a potential sink
for untrusted input. Our case study (\cref{sec:results}) deliberately
targets this class.

\subsection{On-Device Inference and Positioning}
Efficient quantised inference runtimes now make it feasible to run
multi-billion-parameter models on a laptop~\cite{ollama,touvron2023llama}.
\cs\ builds on this to keep the entire pipeline local. To our knowledge,
existing tools occupy adjacent points in the design space---cloud SAST,
cloud LLM review, or local linters without semantic reasoning---but not
the combination of \emph{local}, \emph{multi-modal} (static $+$ dynamic
$+$ LLM $+$ metrics), and \emph{developer-facing} that \cs\ targets.
